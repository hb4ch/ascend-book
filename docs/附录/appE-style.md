# 附录E 写作规范（站内版）

> 面向作者的完整规范见仓库根目录 `STYLEGUIDE.md`；本页是读者可见的精简版（也是作者自查清单）。

## E.1 阅读约定

- 正文不插入行内 `📄 资料:` / `📦 源码:` 标注（该写法已在一编重写中淘汰）。关键论断用**脚注 `[n]`**，完整出处聚合在**每章末尾「本章来源与进一步阅读」**。
- 全局溯源账本见[附录D 来源映射表](./appD-source-map.md)。
- 代码运行性分级（四种标签）见[导读](../index.md)，整段只标一次。

## E.2 术语约定

- 术语第一次出现给出中英对照（如「图引擎（GE）」）；一义一译，全书统一；查[术语表](./appB-glossary.md)。
- 先人话后术语：正文先把难概念用生活化模型讲一遍，再引入正式名称。

## E.3 作者自查清单（每章成稿后）

1. `npm run docs:build`、`check:internal`、`check:source`、`check:terms` 通过（check:links 需网络，CI 处理）；
2. 引用路径在 `/mnt/SATASSDEXT4/cann/<repo>` 真实存在，API 拼写与仓内一致；且**正文无行内 📄/📦 标注**；
3. 每段代码有可运行性标签且可溯源；表格渲染无裸 `|`；
4. 无「昇腾很强大」类空话；性能论断有出处；每章至少 1 张 Mermaid 小结图；
5. 与本书四大目标对齐；核心章目标字数（一编按 8k 中文，二编起质量优先不灌水）；proof read 过一遍。

## E.4 第二编（M2）特别约束

- 每章 ≤5 个**锚点源码文件**讲透（每个 ≤25 行），其余只进章末脚注；禁止逐文件翻译 `runtime/src/`。
- 第4章讲**用法**（对着 `acl_rt.h` 与 example）、第5章讲**机制**（`core/src`）、第6章只写**用户态护照面**（内核源码不在开源仓，需明示）。
- `runtime/example` 与 ACL 程序依赖真机 NPU：一律 `[需真机验证]`；cmodel/CPU-SIM 能力只作旁证。
