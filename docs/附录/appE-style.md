# 附录E 写作规范（站内版）

> 面向作者的完整规范见仓库根目录 `STYLEGUIDE.md` 与 `management/ACCEPTANCE.md`；本页是读者可见的必要约定与作者自查清单。

## E.1 阅读约定

- 正文关键论断用**脚注 `[n]`**，完整出处聚合在**每章末尾「本章来源与进一步阅读」**；全局源码导航见[附录D 来源映射表](./appD-source-map.md)（导航用途，非论断证明）。
- **代码可运行性四类标签**（整段只标一次，置于代码块首行注释或紧随行）：

| 标签 | 含义 |
|---|---|
| `[可在 NPU 运行]` | 来源仓提供的可运行样例；须满足其软硬件条件，不代表本书已在 NPU 复测 |
| `[可用 CPU-SIM 运行]` | 本机 CPU Simulator（如 pto-isa CPU-Sim）可运行 |
| `[需真机验证]` | 依据源码整理，但本机无 NPU，尚需按所附步骤验证 |
| `[示意代码]` | 原理示意，不保证可直接编译运行 |

  **不同验证方式的边界**：四类是执行环境分类，不是准确性等级——标签本身不保证逻辑正确，正确性另由源码、复算或测试支撑。CPU 功能复算（数学对照）、CPU-SIM（如 pto-isa 的**功能模拟**，无硬件时序保证，**不能据此推断 NPU 性能**）与 NPU 实测是三种不同验证，不可互推。本书编写环境无 NPU、未运行 NPU 用例，第二编起按需标注 `[需真机验证]`，验证步骤随段给出，由读者在真机执行。

## E.2 术语约定

- 术语第一次出现给出中英对照（如「图引擎（GE）」）；一义一译，全书统一；统一用词入口见[术语表](./appB-glossary.md)。
- 先人话后术语：先用生活化模型讲清，再引入正式名称。

## E.3 结构与表达约定

- **一个小节讲一个问题**：节内围绕单一论点展开，用例子推进，不并列堆砌。
- **图必须被正文解读**：每图有图注，正文须引用并解释其含义；架构/流程图与所论硬件代际一致（不用 950 图讲 A2 机制）。图用于帮助理解，不为数量凑图。
- 性能论断必有出处；不写「昇腾很强大」式空话（无出处形容词）。

## E.4 作者自查清单（每章成稿后）

1. `npm run verify`（build＋check:internal＋check:source＋check:terms＋word:count）全绿；`npm run check:links` 需网络，由维护者另行执行；当前发布 CI 仅构建站点，未运行该检查。
2. 引用路径在源码快照内真实存在，API 拼写与仓内一致；正文无行内 `📄/📦` 标注。
3. 每段代码有可运行性标签且可溯源（E.1 四类）。
4. 字数遵循 STYLEGUIDE §4 / ACCEPTANCE §1：核心章 8k–12k 中文字；重点算子章（14–17）最低 4k、Flash Attention（18）最低 5k；不足须在交付说明列明覆盖情况，由项目经理验收裁量——**不以「质量优先」自行豁免**。字数统计含脚注与代码注释，不能单独作为完成度证明。
5. 无空话套话；性能数字注明必要条件（版本/架构/shape/dtype/口径/来源）；与本书四目标对齐，成稿前通读一遍。

## E.5 第二编（运行时各章）特别约束

- 每章 ≤5 个**锚点源码文件**讲透（每个 ≤25 行），其余进章末脚注；不逐文件翻译 `runtime/src/`。
- 第4章讲**用法**（对照 `acl_rt.h` 与 example），第5章讲**机制**（`core/src`），第6章只写**用户态可见面**——内核态源码不在开源仓，章内明示此边界。
- `runtime/example` 与 ACL 程序依赖真机：相关代码标 `[需真机验证]`；cmodel/CPU-SIM 能力只作旁证，不等价真机（见 E.1）。
