# 执行标准（ACCEPTANCE）

> 2026-10-09 制定。依据 P0.md 任务与 PLAN-COMPLETION.md 验收重点整理，供项目经理逐章验收执行。项目经理已将字数口径同步至 STYLEGUIDE；本文件补充执行细节，与其共同使用。

## 1. 字数标准（按章类分口径）

| 章类 | 深度目标（中文，正文计） | 最低要求 | 说明 |
|---|---|---|---|
| 核心章（全书主干） | **8k–12k 中文字** | — | 低于 8k 时**必须在交付说明中列明覆盖情况**（写了什么/没写什么/为什么），**由项目经理验收裁量**，pi 不得自行豁免 |
| 重点算子章（ch14–ch17） | 深度目标同上；**最低 4k 中文字** | 4k | 同上：低于 8k 深度目标须列明覆盖情况，由项目经理验收，**禁止以「质量优先」自行豁免** |
| Flash Attention（ch18） | 深度目标同上；**最低 5k 中文字** | 5k | 同上 |
| 非重点章（综述/展望/附录） | 按 STYLEGUIDE 既有要求 | — | 项目经理个案裁量 |

- 字数以 `npm run word:count` 的「中文」列为准；该统计含代码注释与脚注，**不能单独作为完成度证据**，须配合内容覆盖率说明。
- 禁止为凑字重复前章内容；重复引用须以「回指+增量」形式出现。

## 2. 运行性分级（代码块标签）

- **沿用 STYLEGUIDE §3「代码与运行性分级」既有四种标签，不新造、不遗漏**：`[可在 NPU 运行]`（仓内已验证样例）/ `[可用 CPU-SIM 运行]`（如 pto-isa CPU-Sim）/ `[需真机验证]`（逻辑/API 正确但无真机，附验证步骤）/ `[示意代码]`（原理示意，不保证可编译）。
- 本机实际执行记录（命令+输出路径）可作为 `[可在 NPU 运行]`/`[可用 CPU-SIM 运行]` 标签的**附加证据**，不改变标签体系。
- **无真机时不得声称已在 NPU 验证**；CPU-SIM 以实际执行记录为准，无法执行时在章内或交付报告列明缺失依赖，不伪造成功。
- 涉及架构差异处须显式标注：A2/A3（dav-2201 系）与 950（dav-3510）分开表述，禁止混写。

## 3. 来源证据标准

- 每章 3–5 个主要锚点（**文件级**，非仓库/目录级），细粒度证据走脚注；`docs/附录/appD-source-map.md` 为全局账本。
- 关键论断须可溯源到 **固定快照**（management/SOURCE-BASELINE.md 所记 commit）下的 `文件:符号/行号`；区分三类：**源码直接事实 / 文档陈述 / 作者推导**，推导须标注推导依据。
- 性能数字五要素缺一不可：**版本（源仓 commit 或文档日期）、架构、shape/dtype、测量口径、来源**；官方数据与本机实测分开呈现；**禁止推导未经测量的加速比**。
- 引用 CHANGELOG/版本类条目须带日期；目录数量、产品映射、路线图按固定快照表述，附「查证方法」，不写无时间边界的现状断言。

## 4. 图表标准

- 沿用 STYLEGUIDE §6：Mermaid 优先（流程/时序），手写 SVG 用于分层/架构/数据流大图（存 `docs/figures/`，配色按既定调色板，`#e8590c` 统一橙）。
- 每图：中文+英文 alt、斜体图注、正文必须引用并解释；图示架构须与所论硬件一致（不得用 950 图讲 A2 机制）。
- AI 生成概念插图仅限装饰，须标「AI 生成概念插图，非技术图」。

## 5. 全文校验（每章收口必过）

1. `npm run verify`（build + check:internal-links + check:source + check:terms + word:count）全绿，**附完整日志**。
2. 脚注渲染、表格转义、图/代码标签人工过一遍；阅读连续性（前章承诺是否兑现）专项核对。
3. 外链校验单独记录网络限制，不阻塞。
4. 提交按章组织；**收口同步**：frontmatter status、appD、README 里程碑、CHANGELOG。状态只标「初稿/待审/已验收」，**不自行宣布全书完成**。

## 6. 验收流程

pi 交付 → 附：实际修改清单、来源证据表、验证日志、未解决问题 → 项目经理独立抽查（关键 API/同步语义/平台支持/性能数字，不以路径存在代替事实正确）→ 通过则验收、重大问题退回。每轮只处理一个边界清晰的任务。

## 用户新增：可读性与图表

按STYLEGUIDE新增节验收。每章需有可追随主例、循序解释及服务理解的图表；拒绝审查账本式正文、过密大表和文字盒图。保持关键使用条件，细证移脚注。技术验收不代替可读性验收。第21、22章需追加编辑性重写与图表优化；原技术验收保留，不宣称已完成本轮可读性复核。
