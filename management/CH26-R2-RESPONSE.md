## 1. 26.2 拆三短段；删泛化句；地址→缓冲区生命周期；「两条 dynamic 开关」改口

原一大段拆为**三段**，逐段对应：手工职责 → 自动后端 → 内存池策略：

> 段1：「**手工捕获要自己管地址与生命周期**：捕获阶段会把图相关的内存地址**固化**……**重放所用的输入/输出缓冲区需要落在捕获时的地址上并保住生命周期**，具体能怎样更新、何时必须重捕，以官方接口文档为准（示例变量名 `static_*` 只是命名，不构成能力推断的依据）。这意味着**手工管理捕获与输入缓冲区有额外负担**：多一套 shape 就多一份要维护的捕获。」

——「换一批 shape 就要重录一遍」已删（rg=0）；不再把后端多图策略泛化回手工捕获；「维持布局相同」改为**缓冲区地址+生命周期**表述，且「具体能怎样更新、何时必须重捕以官方接口文档为准」——未核 API 约束不新增保证。

> 段2：「于是更常见的选择是把多 shape 交给**自动图后端**……**同一张 FX 图可被多次捕获**，`dynamic=True` 时每见新 shape 即触发一次新捕获。」

> 段3：「内存上，该后端配了两类池策略——……注意这些**多图与内存池策略是自动图后端的管理手段**，不是手工 `NPUGraph` 接口的参数，也不是捕获机制本身对任何 shape 的承诺。」

——“两条 dynamic 开关”改为「多图与内存池策略」（实际只展示了 dynamic=True 重捕与池复用两类事实，review 指认准确）。
