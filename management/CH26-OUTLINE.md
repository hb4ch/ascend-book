# CH26 提纲 —— 已有 PyTorch 模型：图重放、自动融合与写算子的抉择（rev2）

2026-10-10，按 CH26-WRITE 五条纠正修订。证据：`management/CH26-EVIDENCE.md`（下记 EV§x）。主线读者：**手上有一个 PyTorch 模型（或已写好的算子逻辑），想让它在昇腾上更快/更好用**。全章沿一个场景推进：先入口、再讲清两类不同的开销与对应手段、最后才是写算子。概念首现给白话。不设字数目标；两图短小、节点≤6、**图内无证据编号/评审术语**；两路线**不称互斥、不称覆盖 torchair 全部后端**。

## 26.1 入口：先问两个白话问题（~0.6k）

场景：模型在 GPU 上跑得好好的。第一个问题——**你的时间花在哪**：是"每个小算子都向硬件报到一次"的调度开销，还是"算子本身来回搬数据"的执行开销？第二个问题——**你愿意改多少代码**：一行不改（换框架/配置）、改几行（图捕获或换编译后端）、还是动手写算子。本节只给一张「问题→手段」对照小表，四层是**选入口的概念分类，不是必经的调用栈**——白话点明：下面各手段是并列的可选项，任选其一即可起步，不存在"必须逐层穿过"。

## 26.2 调度开销与图重放：capture 一次，replay 多次（~1.2k）

- 白话图捕获/重放：把一段计算录制成"指令带"，回放免重录——解决的是**下发与调度等待**，不是算子内部快慢（EV§E1/E2）。
- aclGraph 模型一段：Stream=任务队列、Event=跨队列约定（EV§E1）。
- `torch.npu.NPUGraph` 三行示例：**标注「博客示例转述、本书未运行」**；static_* 是示例命名，**不读成"只支持静态 shape"**——shape 边界按原文三态写清：单次捕获内地址固化；`dynamic=True` 新 shape 触发**重新捕获**（同 FX 图多次捕获间内存复用默认开）；`dynamic=False` 跨 FX 图池复用默认关、须自证无踩踏（EV§B②/E4'）。
- 何时值得：小算子多、跨流依赖 frequent（EV§E2 原文两条件）；反面一句：单一大算子收益有限（推导，标注）。

## 26.3 执行开销与自动融合：让小算子长在一起（~1.2k）

- 白话融合：把"搬出去再搬回来"的相邻小算子合并成一个内核（EV§D1 背景、autofuse 博客引言）。
- AutoFuse 管线一段：AscGraph→Schedule（多候选 ImplGraph）→AutoTiling（约束→耗时建模→求解）→Codegen（TilingKey 选模板）——讲直觉不堆术语，术语首次出现给白话（EV§D2）。
- 接入=inductor_npu_ext 一个 import＋原 `@torch.compile`（EV§D3；示例代码标「博客转述、未运行」）。
- **两条路线并列小表**（26.2 的图编译后端 vs 本节 Codegen 后端）：介入层次/解决的开销类型/接入改动；明写「**二者不互斥，也不代表 torchair 后端的全集**——torchair 生态还有其他后端，本书仅追此两条有文本证据的线」。

## 26.4 想自己动图：FX Pass 与多流（~0.8k）

torchair 自定义 Pass 一段：签名三参数白话（图/示例输入/配置）→能做什么（改结构、**表达框架原生没有的硬件语义**：scope_enter/exit 包裹流、record/wait 定序）→pre/post 注入点差别（EV§C1/C2）。8 行示意骨架标【文】转述不可运行。收束：这是"框架不动、在图上注入硬件优化"的口子，代价是读得懂 FX 图。
