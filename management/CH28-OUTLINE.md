2026-10-10。证据：`management/CH28-EVIDENCE.md`（下记 EV§x）。定位：全书末章，回答**「软件栈在动，读者该如何安排下一步的学习/验证/迁移」**——不是各仓 changelog 摘抄，也不是 26 章生态重讲。篇幅弹性（无硬指标），预计 3.5–4.5k 中文；1 图 1–2 表。核心纪律：**【发布】/【码】/【推】三种论断分强度呈现；发布日期、提交日期、目标日期三分**。

## 28.1 先立规矩：读路线图的三种证据强度（~0.5k）

用一对具体读法开场：同一句「Tensor API 正式提供」，在 CHANGELOG 里是【发布】（2026-04-30 打包时点），在仓内 docs+样例里是【码】（快照实存）——**后者才允许写「能力存在」，前者只允许写「官方宣告」**。再给三条日期纪律：发布日期（文档标注，本书未核打包行为）≠PR 合入日≠各仓快照日（**逐仓不同，2026-08-21~23，见 SOURCE-BASELINE**）；过去目标日期已到不代表功能完成（无据不判）；不以今天网站状态覆盖快照。asc-devkit roadmap issue#316 仅入口存在【缺口】。

## 28.2 半年时间线：这条栈在往哪走（图①，~0.6k）

图①五节点：PyPTO 0.1.0（1/6）→HIXL FabricMem 文档（3月）→PyPTO 0.2 前端变更（4/10）→asc-devkit beta.1 Tensor API（4/30）→beta.2 调试套件＋HIXL 教程（5月）。旁白两点：节奏（月级）与方向（高层抽象、调试工业化、通信语义升级）——方向判断标【推】。

## 28.3 四条有实证的变化，与它们改变的动作（表①+四短段，~1.6k）

每段固定四拍：**官方宣告（【发布】）→仓内实存（【码】）→对该书读者的动作→条件与边界**。

1. **Tensor API＝Layout 化扩展（实读核验）**：beta.1 宣告；实现核验=mmad_mx.asc 全链 `Te::MakeTensor/Layout/Slice/Mmad`（EV B1），对照老范式样例；**新在 Layout/Shape/Stride 自动推导，且官方自述当前仅赋能 Cube——「新学默认路径改变」不写**，改「Cube/MX 新项目可评估；书内 LocalTensor 并非新生物」。条件：950>9.1.0/dav-3510，未编译未运行。

## 28.4 反面清单：本书不预测什么（~0.4k）

不编四代硬件统一性能排名；不预测上市时间/倍数；不从「Unreleased 无条目」推出无进展（pto-isa 即例）；不把 issue 标题当特性承诺；不拿今天的官网状态修订快照结论。每条一句理由，接 §D 边界清单。

## 28.5 收束：把路线图读成学习计划（~0.3k）

一个可复用的三问模板收尾：**这条变化有没有【码】级实证？我手上有没有验证条件（卡/模拟器）？它动了我书里哪几章的假设？**——并以 Tensor API 为例走一遍三问作示范。末句回扣全书：工具会换代，「从源码取证、分级采信」的方法不变。

## 陷阱与注意（3–4 条）

- 日期混用是最常见错误：引用任何日期先问是哪种日期。
- 【发布】转述当【码】用：「CHANGELOG 说支持」≠「仓内可验证」。
- issue/外链规划内容未读就是未读，不转述。
- 性能数字全部带「文档自述」限定，本书零实测。
